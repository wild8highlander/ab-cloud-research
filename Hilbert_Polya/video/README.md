## What this folder is

The production home of the film companion **"Zeros & Gates: an experiment
in pixels"** (`zeros_and_gates_1080p.mp4`, 210 s, 1920×1080, ambient
score). The scientific storyboard of the film — scene by scene, with the
√N statistics of the montage and the 24-bell zero table at 30-digit
precision — is measured in **Appendix H of the main README**
([`../README.md`](../README.md), Appendix H). This folder holds the other
half of the contract: the two scripts that regenerate the film from
scratch, the production constants of every layer, and the exact commands
that turn them back into the shipped file. The rendered film itself
travels alongside the documentation archive rather than inside it (a
1080p master is not a text file), but everything that produced it is
committed here — the film is as re-derivable as any verdict JSON.

No stock footage, no external assets, no third-party media libraries: the
picture is computed frame by frame with NumPy and Pillow and piped raw
into ffmpeg; the score is synthesized with NumPy and written to WAV by
the standard library. Both scripts draw their randomness from seed
**96** — the package's master seed, the same one the campaigns use — so
the film is literally generated by the laboratory's own randomness, and a
re-render reproduces the shipped cut deterministically.

## The picture — `render.py`

Seven scenes on one timeline, each a pure function of time, joined by
1.6-second crossfades (`FADE = 1.6`, smoothstep-weighted):

| Scene | t (s) | Function | The rule it dramatizes |
|-------|-------|----------|------------------------|
| S1 prologue | 0–20 | `s1` | the zeros as data: 260 stars, the amber critical line, γ₁… one every 1.6 s (mpmath `zetazero`) |
| S2 the wall of gates | 20–50 | `s2` | the 87-gate family as a 7×13 breathing shutter grid |
| S3 the forbidden shortcut | 50–76 | `s3` | typed zeros burn: red sweep, edge burn, ±2.2 px shake |
| S4 the exposure | 76–110 | `s4` | pure noise frames; glimpses never exceed ≈ 0.05 |
| S5 the montage accumulator | 110–160 | `s5` | 600 exposures averaged; one zero locks in every 2 s |
| S6 the spectrum emerges | 160–190 | `s6` | the comb at full contrast; teal gap histogram (GUE widths) |
| S7 epilogue | 190–210 | `s7` | the observatory; "zeros are measured, not typed" |

The heart of the film is the S5 accumulator. Exposures are admitted at
12 per second toward the 600-frame budget, so the budget is reached
exactly at the end of the scene; each exposure is an independent
Gaussian field 𝒩(0.5, 0.5²) plus the hidden comb at amplitude 0.85, and
the displayed image is the running average. Because the sum of k
independent 𝒩(0.5, 0.5²) fields is a single 𝒩(0.5k, 0.25k) field, the
accumulator adds each frame's batch in closed form — one Gaussian draw
per frame, exactly distribution-equivalent to adding k exposures one by
one, and fast enough to render the whole scene in minutes. The on-screen
counter (`combining N exposures · zeros locked: K/24`) reads the same
state variables as the accumulator, so the caption can never disagree
with the image.

Titles and captions are drawn as a post-process overlay (`overlay`),
then the warm-red/cool-blue grade and the grain pass run per frame
before the raw bytes hit ffmpeg's filter chain.

## The score — `soundtrack.py`

Every layer of the soundtrack is specified in the script, and every
layer carries information:

| Layer | Specification |
|-------|---------------|
| Pad chords | D minor add9 (D₂ 73.42 Hz … E₄ 329.63), B♭ major seventh, F add9, C add9 — 26.25 s each, the cycle twice |
| Sub drone | 36.71 Hz + octave, breathing on a 37 s period (amplitude 0.06 ± 0.02) |
| Noise swells | band-limited 120–1800 Hz at every scene boundary (amps 0.05–0.07) |
| Shutter clicks | 2.2–3.4 kHz, 320 s⁻¹ exponential decay, scenes 2 and 4 |
| Zero bells | D-minor pentatonic ladder D₄ 293.66 → B♭₅ 987.77, partials 1 : 2.76 : 5.4, decay 2.1 s⁻¹, echoes 310 ms (0.34) / 620 ms (0.15) |
| Bell cue sheet | 5 sparse prologue chimes; 24 montage chimes, `linspace(112, 157, 24)`, octave lift above the twelfth; 8-note ascending arpeggio from 161 s; D₄ → D₆ epilogue cadence |
| Scene 3 verdict | 55 Hz pulse every 2.6 s + band-limited 900–2400 Hz burn wobble |
| Master | 48 kHz stereo, fade-in 2 s, fade-out 6 s, peak 0.85 |

The bells are the package's statistics played in the audio band: the
accelerating and decelerating rhythm of the 24 montage strikes follows
the unfolded spacings of the real zeros — the GUE content of C8 and
Theorem T10, sonified. The measured table behind them (γₙ at 30-digit
precision, normalized spacings δₙ, the GUE Wigner surmise) is Appendix H,
Section H.5 of the main README.

## How to re-render the film

Everything regenerates from this folder with NumPy, Pillow, mpmath and
ffmpeg on the path. The one-shot render (all 5040 frames plus the audio
mux in a single process):

```bash
python3 video/soundtrack.py    # 1. the score -> video_audio.wav (210 s, 48 kHz stereo)
python3 video/render.py        # 2. the picture + mux -> zeros_and_gates_1080p.mp4
```

The segmented render, which is how the shipped master was produced (each
segment is a self-contained foreground process; the accumulator scene
must stay inside one process because its state spans the scene):

```bash
python3 video/soundtrack.py
python3 video/render.py 0    1200 segA.mp4 x   # S1–S2  (0–50 s)
python3 video/render.py 1200 2640 segB.mp4 x   # S3–S4  (50–110 s)
python3 video/render.py 2640 3840 segC.mp4 x   # S5     (110–160 s)
python3 video/render.py 3840 5040 segD.mp4 x   # S6–S7  (160–210 s)
printf "file 'segA.mp4'\nfile 'segB.mp4'\nfile 'segC.mp4'\nfile 'segD.mp4'\n" > concat.txt
ffmpeg -y -f concat -safe 0 -i concat.txt -c copy silent.mp4
ffmpeg -y -i silent.mp4 -i video_audio.wav -map 0:v -map 1:a -c:v copy \
       -c:a aac -b:a 192k -shortest -movflags +faststart zeros_and_gates_1080p.mp4
```

The fourth argument (`x`) selects no-audio segment mode; drop it only
for the one-shot run. Frame indices are `t × 24`; the segment boundaries
above are the scene boundaries, so every crossfade is rendered intact
inside one segment.

## Conventions

- **One seed.** Both scripts draw from `default_rng(96)`; nothing else
  is randomized. A re-render on any machine reproduces the shipped cut.
- **One version.** The scripts in this folder generate exactly the film
  the documentation describes — 600 exposures, 24 lock-ins, 210 seconds.
  If the storyboard of Appendix H ever changes, this folder is where the
  change is made real; the two documents are intended to be diffed
  against each other.
- **The film ships next to the archive**, not inside it — a 1080p
  master does not belong in a text deliverable, but nothing about it is
  secret: every frame is computed by the committed scripts above.

## The pixel-decoding cut (`pixel_gate_decoding_1080p.mp4`)

The second film is the first one rebuilt as an instrument: 3:06,
1920×1080 at 30 fps, ambient score with one bell per measured zero — and
not a single decorative frame. Its storyboard *is* the measurement of
**Appendix H.8**:

| Stage | Frames | What is computed |
|---|---|---|
| S0 title | 1 card | the pipeline: gates → pixels → decode → det → zeros |
| S1 exposure | 87 | each gate stamps its pixel: (x, y), formula, RGBA payload |
| S2 decode | 51 | row-by-row byte read-back, H_pixels heatmap, 24 eigenlevels, witness strip 17/17 |
| S3 function | 166 | f(E) = det(E·I − H_pixels): sign scan, 24 bracketed zeros, measured-vs-typed cards |
| S4 protocol | 2 | the 24-row measurement table; closing: "zeros are measured, not typed" |

The single committed script
[`pixel_decoding.py`](pixel_decoding.py) regenerates the entire
measurement end-to-end (canvas → decode → recurrence → bisection →
verification) and writes its own log into `./pixel_output/`. The shipped
artifacts of that run are committed beside it:

- [`pixel_decoding_data.json`](pixel_decoding_data.json) — the full
  measurement log: 87 gate records (family, pixel, value, formula), the
  α/β entries, the witness strip and its 17/17 verification, the 24
  measured zeros, the typed mpmath references, per-zero deltas, and the
  scorecard (max |Δ| = 1.26×10⁻⁷, RMS = 4.98×10⁻⁸, PNG round-trip
  byte-identical);
- [`pixel_decoding_canvas.png`](pixel_decoding_canvas.png) — the master
  canvas: 25×25 RGBA, the big pixel formula itself (24×24 lattice +
  calibration column);
- [`pixel_decoding_matrix.png`](pixel_decoding_matrix.png) — H_pixels as
  read back from the PNG bytes, all 70 structural entries annotated;
- [`pixel_decoding_spectrum.png`](pixel_decoding_spectrum.png) — the
  measured zero staircase against the Riemann–von Mangoldt smooth count.

Run `python3 pixel_decoding.py` (needs `numpy`, `mpmath`, `pillow`) and
the report ends with the sentence the whole package is built around:
*zeros are measured, not typed.*

**Algebraic form (2026-10-13).** The Lanczos step of this pipeline is now
backed by a closed-form algebraic function Φ (Hankel determinants D/S of
the squared-residue measure νₙ ∝ |Res(1/ζ, ρₙ)|²): the canvas is the Q22
quantization of Φ(γ, ν), the det-recursion decode is the inverse branch,
and the identity Σαₙ = Σγₙ makes the committed witness pair
`mean_alpha`/`mean_gamma` an exact built-in checksum. Library, exact-ℚ
verification and the report live in [`../algebraic_map/`](../algebraic_map/).

**Honesty note (audit, 2026-10-13).** The zeros are prescribed as the
nodes of the measure (inverse Jacobi problem); the film demonstrates
lossless pixel transport with witness-verified integrity — not an
arithmetic generation of the operator. The blind counterpart (pixels
from arithmetic, zeros as the prediction) is roadmap step N7. The
committed `pixel_decoding_data.json` was regenerated on 2026-10-13 so
that its schema equals the script's output; the earlier committed
artifact carried an off-by-one witness check from an older script
revision.
