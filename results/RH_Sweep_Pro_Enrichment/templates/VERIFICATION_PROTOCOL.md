# Протокол верификации прогона RH-Sweep PRO (Verification Protocol)

> Независимая проверка результатов прогона сторонним проверяющим или
> самим автором «свежим взглядом». Цель: отличить физический сигнал от
> методических артефактов. Редакция 1.0 · 2026-10-16

## 0. Предпосылки

Проверяющему нужны: эта папка прогона, Julia ≥ 1.9 с тем же RH_Sweep_Pro_D.jl,
~30 минут. Все шаги выполняются БЕЗ пересчёта диагонализаций — только
по сохранённым файлам (если не указано иное).

## 1. Целостность папки

```bash
sha256sum -c manifest.sha256     # или проверка вручную по списку
```

Любое расхождение → папка менялась после подписи; использовать
зафиксированную ревизию из git.

## 2. Внутренняя согласованность (5 минут)

| Проверка | Как | Ожидание |
|:--|:--|:--|
| N_AB согласован | `L=64 → eigs_per_seed=⌊0.3·L²⌋`; N_AB = n_seeds·EPS | = строка `n_eigs` в metrics.csv |
| ζ-нулей | строк в `csv/zeta_zeros.txt` | = `n_zeta_zeros` в config.json |
| ⟨r⟩ по сырому спектру | пересчитать из `ab_eigs.txt` (см. скрипт ниже) | = `r_mean` ± 1e-6 |
| Тесты | пересчитать пороги из колонок metrics.csv | = `tests_passed` |
| Score | пересчитать из 12 компонент по весам 15/10/5 | = `composite_score` ± 0.01 |

```julia
# быстрый пересчёт ⟨r⟩ из сырого спектра
eigs = vec(readdlm("csv/ab_eigs.txt"))
d = diff(sort(eigs))
r = mean(min.(d[1:end-1], d[2:end]) ./ max.(d[1:end-1], d[2:end]))
```

⚠️ Пересчёт по конкатенированному спектру даёт ⟨r⟩ «одной пачкой»;
конвейер считает по-блочно (B=250) — расхождение до ~0.001 допустимо.

## 3. Независимая проверка кривых (10 минут)

1. Открыть `curves/*.csv` в любом инструменте (Python/Excel).
2. Пересчитать `RMS(R2_ab − R2_gue)`, корреляцию Пирсона `K_ab↔K_gue` и
   `K_ab↔K_zeta`.
3. Сверить с `metrics.csv`: `R2_rms_GUE`, `K_corr_GUE`, `K_corr_zeta`.
4. Построить K(t): ramp до t=1 и plateau=1 — визуальный признак GUE;
   провал plateau ниже ~0.9 → блоки выборки смешаны (артефакт сшивки).

## 4. GUE-пол и научная форма утверждения

Слабое утверждение: «Score = 84.85». Сильное утверждение:
«Score превышает GUE-пол метода на Δ = 84.85 − Score(пол)».

1. Прочитать `gue_floor.json` → `metrics.composite_score`.
2. Вычислить Δ_excess.
3. В README утверждения формулируются через Δ_excess, а не через
   абсолютный Score.
4. Если `gue_floor.json` отсутствует — пол не измерен; пометить README
   «пол метода: не измерен» и выполнить `gue_floor_control`.

## 5. Значимость (multi-seed)

1. Открыть `sensitivity/multi_seed.csv`.
2. Для ключевых метрик (⟨r⟩, K corr(ζ), Score) вычислить mean ± 2·std.
3. Сравнение двух конфигураций корректно, только если интервалы
   mean±2·std не пересекаются. Точечные сравнения без разброса —
   не публиковать.

## 6. Известные ловушки интерпретации

| Ловушка | Пояснение |
|:--|:--|
| Вырожденные графики 03/04 | heatmap/progress одиночной точки не несут смысла — смотреть только 01/02/05 |
| `chi2_pvalue` | это exp(−χ²/2), а не p-value; не цитировать как вероятность |
| `spectral_compressibility` | прокси на L=9–10, а не lim Δ₃/L; для публикации пересчитать на сетке L |
| Цель ⟨r̃⟩ | верифицированный эталон 0.3602 (не 0.3997 из старой панели) |
| E(s=1) = 0.171 | цель для GUE; значения выше означают ослабленное отталкивание уровней |
| Рациональный α | полосы Хофштедтера занижают K corr(ζ) — это физика, а не баг |
| Сравнение платформ | побайтовое совпадение только в пределах Julia+BLAS; иначе сравнивать метрики, не спектры |

## 7. Критерии вердикта

| Статус | Условие |
|:--|:--|
| PASS | целостность ✓ · согласованность ✓ · кривые воспроизводятся ✓ · пол измерен ✓ |
| PASS с оговорками | PASS, но без gue_floor/multi-seed (помечено в README) |
