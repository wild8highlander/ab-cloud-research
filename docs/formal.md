# Formal verification — Lean 4 · Coq · Agda · Isabelle

The [formal layer](https://github.com/wild8highlander/ab-cloud-research/tree/main/formal)
is the machine-checked wing of the AB-Cloud program. Four independent proof
assistants certify the exact algebraic skeleton of the verification suite,
and the Lean 4 executable **re-derives the frozen reference numbers of the
flagship run directly from the raw ζ-zero dataset** — an exit-code-gated CI
check, not a promise.

## Why

The 10-language suite answers *"could this be a numerical accident?"*.
The formal layer answers the next question — *"who verifies the verifier?"*:

1. **Exactness where exactness is possible.** The algebraic skeleton —
   the residual sum behind $b(N) = \tfrac{1}{N}\sum_{k\le N}|\gamma_k - \tilde\gamma_k|$,
   the Gram offset lattice behind $\tilde\gamma_k = 2\pi k / W(k/e)$, the
   flux certificates, the Hurwitz group orders and the trace identity
   $\operatorname{Tr}(AB) = \operatorname{Tr}(BA)$ — is *proved*, not computed.
2. **A 12th language, inside a proof assistant.** The Lean executable is a
   dependency-free Float64 port of the Python reference pipeline
   (Lambert W → Gram points → b(N) ladder → unfolded spacings → GUE CDF →
   KS / Cramér–von Mises → log–log fit) reading the same frozen dataset.
3. **CI gates.** [`formal.yml`](https://github.com/wild8highlander/ab-cloud-research/blob/main/.github/workflows/formal.yml)
   compiles all four assistants on every push; the Lean executable fails the
   build if any frozen number drifts beyond its committed tolerance.

## Quick start

=== "Lean 4 (flagship: theorems + executable)"

    ```bash
    cd formal/lean4
    lake build && lake exe abcloud-verify
    ```

    Toolchain pinned in `lean-toolchain` (`v4.19.0`); no Mathlib — the build
    finishes in under a minute.

=== "Coq"

    ```bash
    cd formal/coq
    coq_makefile -f _CoqProject -o Makefile.coq && make -f Makefile.coq -j2
    ```

=== "Agda"

    ```bash
    cd formal/agda
    agda -i . -i . ABCloud.agda
    ```

    Builtins only — no standard-library dependency.

=== "Isabelle/HOL"

    ```bash
    isabelle build -D formal/isabelle
    ```

    Imports `Main` only; works with Isabelle2024/2025.

## Honesty notes

- Nothing here *proves the Riemann Hypothesis* — it proves the arithmetic
  the numerical program stands on, and re-derives its numbers.
- The KS p-value is reported informationally but not tolerance-checked
  (exponentially libm-sensitive); D, W², the b(N) ladder and the fit are
  gated instead.
- All four developments have **zero external dependencies** — the audit
  surface is the repository itself.
