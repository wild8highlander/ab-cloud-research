# Публикация репозитория на GitHub прямо с Android (Termux)

Этот комплект позволяет **полностью обновить репозиторий
`https://github.com/wild8highlander/ab-cloud-research` прямо с телефона**,
не включая компьютер. Нужно лишь: установить Termux, распаковать архив,
запустить скрипт и ответить на его вопросы — имя пользователя и токен
(или вход через браузер). Всё остальное скрипт сделает сам.

## Состав комплекта

| Файл | Назначение |
|------|------------|
| `termux/install_and_push.sh` | главный скрипт: ставит пакеты, делает push, проверяет результат |
| `termux/README_RU.md` | эта инструкция (подробная) |
| `HOW_TO_PUSH_FROM_ANDROID.md` | короткая шпаргалка в корне репозитория |

---

## 1. Что понадобится

- Телефон или планшет на **Android 7.0 или новее**.
- Свободное место: **не менее 3 ГБ** (сам архив ≈ 0,7 ГБ + распакованные
  файлы ≈ 1,5–2 ГБ + место для работы git).
- Интернет, желательно Wi-Fi: распаковка и отправка тянут сотни мегабайт.
- Аккаунт GitHub с правами на репозиторий
  `wild8highlander/ab-cloud-research`.

## 2. Шаг 1 — установить Termux

**Важно: ставьте Termux из F-Droid, а не из Google Play.** Версия из Play
Market устарела и больше не обновляется, из-за неё бывают ошибки пакетов.

1. Откройте в браузере телефона: <https://f-droid.org/packages/com.termux/>
2. Нажмите **Download APK** и скачайте файл.
3. При установке Android спросит разрешение «устанавливать из этого
   источника» — разрешите и установите приложение.

Альтернатива, если F-Droid недоступен: официальные релизы Termux на
GitHub — <https://github.com/termux/termux-app/releases> — берите файл
`termux-app_*_arm64-v8a.apk` (подходит большинству современных телефонов).

## 3. Шаг 2 — первичная настройка Termux

Откройте Termux и выполните по очереди две команды (набирайте точно как
здесь; ввод — кнопка Enter на экранной клавиатуре):

```bash
pkg update -y && pkg install -y git curl unzip
termux-setup-storage
```

- После `termux-setup-storage` Android спросит разрешение на доступ к
  файлам — нажмите **Разрешить**. Это даст Termux доступ к папке
  «Загрузки», где лежит архив.
- Если `pkg update` жалуется на зеркала — выполните `termux-change-repo`,
  выберите любое зеркало (например, Grimler) и повторите команду.

## 4. Шаг 3 — распаковать архив

1. Скачайте **ab-cloud-research-v1.1.0.zip** на телефон — он попадёт в
   папку «Загрузки» (Download).
2. Распакуйте архив в домашнюю папку Termux (именно в `~`, а не в
   общую память /sdcard — там git работает с ошибками):

```bash
cd ~
unzip ~/storage/downloads/ab-cloud-research-v1.1.0.zip -d ~/repo-ab-cloud
```

3. Проверьте, что всё на месте:

```bash
ls ~/repo-ab-cloud
```

Должны быть видны `README.md`, `push_to_github.sh`, папка `termux` и
другие файлы проекта.

> Если вы уже распаковали **старую** версию архива — не пересобирайте
> всё заново: возьмите лёгкий файл **termux-push-kit.zip**, скопируйте
> его в существующую папку репозитория и выполните
> `unzip termux-push-kit.zip` внутри неё. Он добавит папку `termux`
> и шпаргалку, после чего сразу переходите к шагу 4.

## 5. Шаг 4 — запустить скрипт

```bash
cd ~/repo-ab-cloud
bash termux/install_and_push.sh
```

Дальше скрипт всё сделает сам и задаст всего несколько вопросов.

## 6. Вопросы скрипта и как на них отвечать

1. **«Куда пушим (URL репозитория GitHub)»** — просто нажмите Enter:
   адрес вашего репозитория уже вписан по умолчанию.
2. **Способ входа** — два варианта:
   - **1 — PAT-токен**: введите имя пользователя (Enter = `wild8highlander`)
     и вставьте токен. При вводе токен не отображается — это нормально,
     так и задумано. Скрипт проверит токен через API GitHub ещё до отправки.
   - **2 — вход через браузер**: скрипт установит GitHub CLI, покажет
     **одноразовый код** вида `ABCD-1234` и откроет браузер на странице
     `https://github.com/login/device`. Введите код в браузере, нажмите
     Authorize — и всё, Termux войдёт без всякого токена. Это самый
     простой способ, если не хочется возиться с созданием токена.
3. Скрипт проверит право на запись, заберёт текущее состояние GitHub,
   сравнит историю и отправит ветку `main` вместе с тегами.
4. Если истории на GitHub и в архиве расходятся (например, на GitHub
   что-то появилось после этого архива), скрипт спросит разрешение
   обновить ветку принудительно — с защитой `--force-with-lease`
   (чужие коммиты, сделанные позже момента сверки, будут отброшены).
   Отвечайте **Y** (или просто Enter).
5. В конце скрипт предложит **открыть репозиторий в браузере** —
   удобно сразу проверить, что последний коммит обновился.

Весь сеанс выглядит примерно так:

```text
▸ Termux обнаружен.
Куда пушим (URL репозитория GitHub) [https://github.com/wild8highlander/ab-cloud-research.git]:
  Способ входа в GitHub:
    1) PAT-токен — ввести имя пользователя и токен (ввод скрыт)
    2) Браузер   — одноразовый код через GitHub CLI (gh), всё в браузере
  Выбор [1]: 2
  Сейчас появится ОДНОРАЗОВЫЙ КОД (вида XXXX-XXXX). …
✔ Вход выполнен как: wild8highlander
▸ Проверяю доступ к репозиторию wild8highlander/ab-cloud-research…
✔ Право на запись подтверждено.
▸ Синхронизирую с GitHub (fetch)…
▸ Отправляю ветку main на GitHub…
✔ Подтверждено: на GitHub ветка main = a1b2c3d
=============================================================
  ГОТОВО! Репозиторий обновлён на GitHub.
=============================================================
```

## 7. Как создать PAT-токен (для способа 1)

1. На любом устройстве откройте: <https://github.com/settings/tokens>
2. **Generate new token → Generate new token (classic)**.
3. Note — любое имя, например `termux-push`.
4. Expiration — 30 дней или другой срок на ваш выбор.
5. Отметьте галочку **repo** (полная область).
6. Нажмите **Generate token** и скопируйте токен (начинается с `ghp_`).
   Он показывается **только один раз** — сохраните его в менеджере
   паролей, чтобы переиспользовать при следующих обновлениях.

Fine-grained вариант (строже и безопаснее):
<https://github.com/settings/personal-access-tokens> →
Repository access → только `ab-cloud-research` → Permissions →
**Contents: Read and write**.

## 8. Что именно делает скрипт

- проверяет окружение Termux и доустанавливает `git`, `curl`, `gh`,
  если их нет;
- включает wake-lock, чтобы Android не «убил» Termux во время отправки;
- если репозиторий лежит в общей памяти (/sdcard), автоматически
  переносит его во внутреннюю память Termux (`~/repo-ab-cloud`);
- коммитит незафиксированные изменения, если такие найдутся;
- настраивает remote `origin` на указанный вами репозиторий;
- сравнивает локальную историю с GitHub и выбирает безопасный режим
  push (fast-forward или force-with-lease с явным вашим согласием);
- отправляет ветку `main` и теги;
- по `ls-remote` сверяет, что GitHub получил именно ваш коммит;
- открывает репозиторий в браузере (по желанию).

Безопасность: токен и данные входа живут **только в оперативной памяти**
процесса скрипта. Они не пишутся на диск, не попадают в `.git/config`,
не сохраняются в истории команд и уничтожаются при завершении скрипта.

## 9. Если что-то пошло не так

| Симптом | Что делать |
|---------|------------|
| `Токен не принят (HTTP 401)` | Токен неверный или истёк — создайте новый (раздел 7). |
| `HTTP 403` / «нет права записи» | Для classic отметьте область `repo`; для fine-grained дайте Contents: Read and write именно на этот репозиторий. |
| `! [rejected] ... non-fast-forward` | Так и задумано: скрипт сам предложит force-with-lease — ответьте Y (Enter), если хотите именно обновить репозиторий содержимым архива. |
| `No space left on device` | Освободите место: нужны ~3 ГБ. Старые распаковки удалите: `rm -rf ~/repo-ab-cloud` и начните заново. |
| Termux «засыпает», push прерывается | Скрипт сам ставит wake-lock; дополнительно держите Termux открытым и не давайте телефону уснуть на время отправки. |
| `pkg` ругается на зеркала | Выполните `termux-change-repo`, выберите другое зеркало, повторите. |
| Вставили токен куда-то не туда | Отзовите токен: <https://github.com/settings/tokens> → Delete, и создайте новый. |
| Скрипт запущен из папки на /sdcard | Нормально: скрипт сам скопирует репозиторий в память Termux и продолжит оттуда. |

## 10. Ручной вариант (без скрипта)

Если хочется сделать всё руками:

```bash
cd ~/repo-ab-cloud
git remote add origin https://github.com/wild8highlander/ab-cloud-research.git
git push https://ВАШ_ЛОГИН:ghp_ВАШ_ТОКЕН@github.com/wild8highlander/ab-cloud-research.git HEAD:main --force-with-lease
```

Подставьте свой логин и токен вместо `ВАШ_ЛОГИН` и `ghp_ВАШ_ТОКЕН`.
Токен при этом останется в истории команд — после отправки выполните
`history -c`, а лучше просто используйте скрипт, который ничего не
запоминает.

## 11. Мини-FAQ

**Можно ли пушить так несколько раз?** Да, скрипт можно запускать
сколько угодно: он каждый раз сам синхронизируется с GitHub и выбирает
безопасный режим обновления.

**Обновятся ли релизы и теги?** Ветка `main` обновляется всегда, теги
отправляются следом за ней. Создание GitHub Releases выполняется на
странице репозитория вручную.

**Что если на GitHub уже есть коммиты новее этого архива?** Скрипт
сообщит о расхождении и спросит, заменять ли содержимое. Сначала
убедитесь, что новее только то, что вы добавляли сами; содержимое
архива отправится поверх.

**Нужно ли это делать на компьютере быстрее?** Да, на компьютере
проще: `./push_to_github.sh` в корне репозитория — тот же диалог.
Скрипт из `termux/` — полная замена для случая «под рукой только телефон».
